# Spotlight

A fast, accessible command-menu primitive — port of [pacocoursey/cmdk](https://github.com/pacocoursey/cmdk) adapted to this codebase's conventions. Use it for command palettes (⌘K-style), action menus, fuzzy-search UIs, or any list-with-search interaction where the input drives selection.

Built on `@radix-ui/react-dialog` for the modal variant. The list itself is a plain composable React tree — no portal needed for the inline version.

## Accessibility

Spotlight is a fully-keyboard-operable command menu modelled on the [WAI-ARIA combobox / listbox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/).

- **Roles** — the root has `role="combobox"` semantics via the input + list pairing. Items render as listbox `options`; `SpotlightGroup` wraps related items with `role="group"` and a labelled heading.
- **Accessible name** — pass `label` to `Spotlight`. The label is rendered visually hidden inside the menu (standard screen-reader-only recipe) and wired up via `aria-labelledby`. When using `SpotlightDialog`, the same `label` is also the dialog's accessible name.
- **Selected item** — the active item carries `aria-selected="true"` and `data-selected="true"`; the input's `aria-activedescendant` points at it so focus stays on the input while selection moves.
- **Disabled items** — `disabled` items get `aria-disabled="true"` and are skipped by keyboard navigation.
- **Empty / loading states** — `SpotlightEmpty` only renders when there are zero filtered results; `SpotlightLoading` exposes a `label` prop you should use to describe what's loading.
- **Localization** — see the [Localization section](#localization) for translating the visually-hidden label and other strings.

Full keyboard map below.

## Keyboard navigation

| Key | Action |
|---|---|
| `ArrowDown` / `ArrowUp` | Move selection to next / previous item |
| `Home` / `End` | Jump to first / last item |
| `Enter` | Activate the selected item (`onSelect`) |
| `Ctrl+J` / `Ctrl+N` | Same as `ArrowDown` (Vim bindings, on by default) |
| `Ctrl+K` / `Ctrl+P` | Same as `ArrowUp` (Vim bindings) |
| `Alt + ↑/↓` | Jump to previous / next **group** |
| `Meta + ↑/↓` | Jump to first / last item |

Disable Vim shortcuts with `vimBindings={false}`. Disabled items are skipped automatically.

## Filtering

By default, items are fuzzy-matched against the search query using a `command-score` algorithm — exact prefix matches rank highest, scattered character matches rank lower. Pass a custom `filter` function (returning 0–1) to override. Pass `shouldFilter={false}` to take full control yourself (you render the items, Spotlight only handles navigation).

## Sub-components

| Component | Role | Notes |
|---|---|---|
| `Spotlight` | Root container | Holds shared state; required wrapper |
| `SpotlightInput` | Search input | `role="combobox"` wired to the list |
| `SpotlightList` | Listbox container | Sets `--spotlight-list-height` CSS var for animations |
| `SpotlightItem` | Selectable option | Pass a stable `value` if children may change |
| `SpotlightGroup` | Heading + items wrapper | Items stay together when sorting |
| `SpotlightSeparator` | Visual divider | Hidden while searching unless `alwaysRender` |
| `SpotlightEmpty` | Renders when nothing matches | Auto-toggled by filter count |
| `SpotlightLoading` | Async-loading indicator | `role="progressbar"`. Defaults to a `<Spinner />`; pass children to swap in a custom visual. |
| `SpotlightDialog` | Modal wrapper | Built on Radix Dialog |

## Styling

The component ships with minimal default styles in `Spotlight.module.css`. Each part exposes a `data-spotlight-*` attribute (`data-spotlight-input`, `data-spotlight-item`, `data-spotlight-list`, etc.) you can target in your own CSS. Items expose `data-selected="true"` and `data-disabled="true"` for state-driven styling.

```css
[data-spotlight-item][data-selected='true'] {
  background: var(--color-hover);
}
```

For app-specific look and feel, prefer the standard pattern (`className` + a CSS module) over relying on the `data-*` selectors directly.

## Localization

Three pieces of text are user-visible to screen readers and must be localized for non-English apps:

| Where | What | Notes |
|---|---|---|
| `<Spotlight label="…">` | The composite's accessible name. | **Required prop** — no default. TypeScript will fail the build if you forget it. |
| `<SpotlightList label="…">` | The listbox's accessible name. | **Required prop** — no default. |
| `<SpotlightLoading label="…">` | The progressbar's accessible name. | **Required prop** — no default. |

The component renders no other user-visible English text. Visible content (item labels, group headings, placeholder text) is fully caller-supplied and naturally goes through your i18n layer.

## Origin

Ported from [pacocoursey/cmdk](https://github.com/pacocoursey/cmdk) with the following adaptations:

- Split into one file per sub-component (matches our `components/` convention).
- Types tightened — no `any`, no `MutableRefObject`, no implicit `null` returns.
- `cmdk-*` HTML attributes converted to standard `data-spotlight-*` so the markup is valid HTML.
- Internal helpers extracted into `constants.ts`, `context.ts`, `helpers.ts`, `types.ts`, `utils.ts`.
- Unit tests added (the upstream lib only ships Playwright tests).
