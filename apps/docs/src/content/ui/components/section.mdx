# Section

A semantic `<section>` landmark with a tiered vertical-rhythm preset. Use it to separate major regions of a page (hero, features, footer).

Section **always** renders a `<section>` element and **requires** an accessible name via `aria-label` or `aria-labelledby`. TypeScript will refuse to compile without one. If you need vertical-rhythm padding on a non-section element, use a `<div>` (or `<Box as="…">`) with CSS in your component's module instead.

The `size` prop chooses one of four pre-defined vertical-padding tiers. There is no raw `py` prop — that would compete with the design system's CSS modules. If the four tiers aren't enough for a specific page, write the override in the consuming component's CSS module via `className`.

## Why a name is required

A `<section>` element only becomes a navigable landmark for screen readers if it has an accessible name. The accessible-name algorithm checks `aria-labelledby` → `aria-label` → `title`, in that order — **it does not auto-derive the name from a child heading**. A `<section>` with a visible `<h2>` inside but no `aria-*` attribute is announced as a generic group (or skipped entirely) by most screen readers — effectively a `<div>` for landmark navigation.

The recommended pattern points `aria-labelledby` at the visible heading's id. **Always generate the id with React's `useId()` hook** so two instances of the same component never clash:

```tsx
import { useId } from 'react';

function PricingSection() {
  const headingId = useId();
  return (
    <Section aria-labelledby={headingId}>
      <h2 id={headingId}>Pricing</h2>
      …
    </Section>
  );
}
```

`useId` is stable across SSR and client hydration, doesn't require `'use client'`, and never collides across instances. The same rule applies to every ARIA id wiring (`aria-describedby`, `aria-controls`, etc.) — never hardcode the string.

This way the heading stays visible *and* the region is named "Pricing" in landmark navigation.

All standard HTML attributes are also accepted. Pass `className` to extend Section's styles from a CSS module.

## Accessibility

- **Always provide a name.** TypeScript enforces it — `<Section>` without `aria-label` or `aria-labelledby` is a compile error.
- **Prefer `aria-labelledby`** when there's a visible heading. The screen reader announces the visible label, which stays in sync if the text changes.
- **Use `aria-label`** only when there is no visible label nearby — e.g. a section with only an image or interactive control.
- **Don't nest sections more than 2–3 deep.** Each `<section>` adds to the heading outline and creates a landmark; too many flattens the structure.
- **Headings inside the section follow the document outline.** If the Section is at the same level as another, use `<h2>`. If nested inside another section that uses `<h2>`, use `<h3>`. Section itself doesn't render headings — your content does.
